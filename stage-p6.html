0先看懂战场：四类轮次和一个万能框架

AI 应用岗的面试结构和传统前端面试完全不同。把准备时间按轮次分配，比按知识点分配有效得多。

轮次考什么怎么准备
编码轮 算法题过了基本线就够（LRU、合并区间这一档），重点常被追问「并发场景怎么办」 别把时间全砸在这。刷到能过线即停，剩下的时间给系统设计
系统设计轮
主战场		 设计一个客服 agent / 多租户 RAG / 评测平台 用下面那个六段框架，每个主题各练一遍，限时 25 分钟讲完
领域深挖
挂人最多		 RAG 故障定位、eval 设计、上下文管理、失败兜底 拿你自己项目的真实 bad case 练：每个域准备 2 个「我遇到过、我这样定位」的故事
行为轮 「讲一个你做的 agent 线上出问题的故事」——几乎必问，且是资深与否的过滤器 准备 1 个「出问题 → 怎么发现 → 怎么定位 → 改了什么 → 现在怎么防」的完整叙事，这里必须显示你是资深

一个万能答题框架（六段）

遇到任何设计题、开放题，按这个顺序说。它的作用是让你在前 60 秒就显出结构感：

  1. 目标：用户 / 业务要什么结果（一句话，别铺垫）
  2. 约束：延迟、成本、隐私、风险上限——先框死边界
  3. 怎么算成功：eval 与判据。这一步先说，会让面试官立刻高看你一眼
  4. 最简可行架构：能不用 agent 就不用，先给最小方案
  5. 失败模式：在哪断、怎么观测、怎么恢复
  6. 取舍：为什么不选另一种方案，代价是什么
为什么第 ③ 步这么关键

大部分候选人从「我打算用向量库 + LangGraph」开始讲——那是第 ④ 步的内容，而且没有 ①②③ 支撑时听起来像抄来的。而先说「我们怎么算成功」，等于当场证明你是个工程师：你知道要先有尺子再动手。这句话和你 W05 就在做的事是同一件事，只是换到面试场景说。

W22材料：让陌生人愿意给你 45 分钟

第 22 周 · 简历和作品集页的唯一目标：让对方产生一个具体的追问。不产生追问的材料等于被拒。

P6-1 简历 v3：一页，五块，每块都能撑住追问 周六 3h
为什么：v0 是「翻译已有经验」，v3 是「用真实数据支撑」。区别在于：v0 只能说「我做了什么」，v3 能说「效果是多少、代价是什么」。
结构（严格一页，顺序不要改）
块内容行数必须包含
一句话定位旧优势 + 新能力 + 目标岗位1 行不出现「转型/学习/热爱」
项目3 个项目，每个 3–4 个 bullet约半页数字 + 取舍 + 链接
工作经历倒序，每段 2–3 个 bullet约 1/3 页只留和 AI 系统相关的
技能按域分组，不打熟练度3–4 行分「模型/检索/运行时/评测/工程」
教育一行1 行—
一句话定位（三个版本，选一个）
A（偏产品）：10 年前端工程经验，擅长复杂交互与性能优化；独立完成带评测的 RAG 问答
   与可恢复 agent 运行时，能一个人从交互做到部署。

B（偏平台）：10 年后端/前端工程经验，专注分布式系统与性能；近半年构建可观测的 agent
   运行时（checkpoint / 审批 / trace），关注长任务的可靠性。

C（偏交付）：10 年工程经验，做过多个 0→1 项目；近半年交付两个 LLM 应用（含评测体系与
   成本控制），擅长把不确定的模型能力包装成可用的产品。
项目 bullet 的四段公式

背景约束 → 我做了什么选择 → 数据结果 → 代价或局限。最后一段是 90% 的人漏掉的，也是最能证明你不是在吹的部分。

反面（大多数人的写法）正面（v3 写法）
「使用 RAG 技术实现知识库问答系统，提升检索准确率」 「为 240 页内部文档搭建问答系统：对比 3 种分块策略（固定/递归/标题感知），标题感知的 recall@5 达 0.83（纯向量 0.67）；混合检索 + 重排在 30 条标注集上把 MRR 从 0.51 提到 0.72，代价是 P95 延迟 +310ms」
「实现 Agent 系统，支持多轮工具调用」 「手写 agent 运行时（无框架）：3 层兜底（重复调用检测 / token 预算 / 总超时）使注入 5 类故障时不出现未捕获异常；SQLite/Postgres checkpoint 支持 kill -9 后恢复，重启后不重复执行副作用（幂等键 = run+step+参数摘要）」
「优化系统性能，降低成本」 「三档模型路由 + prompt 前缀缓存：单任务成本 $0.0052 → $0.0031（-40%），30 条 eval 通过率仅下降 1 个点（95% → 94%）；缓存命中率 62%」
产物notes/resume-v3.md + 导出 PDF（一页）
验收 ① 一页，不超；② 每个项目 bullet 都有数字；③ 至少 3 处写了代价/局限；④ grep -E "转型|学习|热爱|了解|熟悉" 无输出；⑤ 两个业内人看过，能分别说出「这人做过什么」。
卡住怎么办
  • 「一页放不下」：删工作经历里最早的一段，或把 3 个项目砍成 2 个（每个写深一点）。一页是硬约束——超页会被认为「不会抓重点」。
  • 「数字不好看」：照实写，配「已知问题」。60% 的正确率 + 归因分析 > 「效果显著」。
  • 「不知道代价怎么写」：每个技术选择问一句「它让我放弃了什么」，答案就是代价。
P6-2 作品集页：一屏之内看完三个项目 周日 2.5h
为什么：简历附件可能是 PDF，但作品集页是一个可点的链接——对方在手机上就能看，还能直接点进 demo。这对转岗候选人尤其重要，因为你缺「AI 工作经历」，需要别的证据补。

│  数字：recall@5 0.83 · 引用可追溯 96% · 首字 1.1s │

│  ...                                         │

└─────────────────────────────────────────────┘

每个项目只放四样：一句话、三个数字、一个「最难的决定」、一个链接。不要放技术栈图标墙。

「我做的最难的决定」这一栏为什么值钱

它把一个「做过项目的人」变成「做过判断的人」。招聘方招的是判断力，不是执行力。写的时候用固定句式：「我在 A 和 B 之间选了 A，因为 C；代价是 D。」

产物一个静态页（可以用 P5 的 Next.js 加一个 /portfolio 路由，或直接一个 HTML）
验收手机打开一屏内能看到三个项目和联系方式；所有链接可点且不 404。
卡住怎么办
  • 「设计不好看」：用纯文本 + 间距 + 一条分割线就够。信息密度 > 视觉花活。这页的读者是在扫，不是在看。
  • 「没有三个项目」：两个也行。一个 RAG + 一个运行时已经能覆盖大部分考点。宁可两个写深。

W23表达：90 秒讲清一个项目，8 个追问不卡壳

第 23 周 · 这一周全部是说的训练。写下来、录音、回听、改。不要只在脑子里过。

P6-3 项目四段法 + 每个项目预演 8 个追问 周六 3h
为什么：面试官问「介绍一个项目」时，他在评估三件事——你是否真的做过、你是否有判断力、你能不能把复杂的事讲清楚。四段法同时覆盖这三点。
90 秒版四段（按这个顺序，不要跳）
段时长说什么要点
1 问题15s什么场景、什么约束、为什么值得做给具体规模（240 页、30 条测试集），别说「一个知识库」
2 方案30s整体分几层，关键选择是什么讲「为什么这么分」，不要讲实现细节
3 数据25s2–3 个指标 + 口径必须说清「在什么测试集上」
4 取舍20s最难的决定 + 代价 + 现在会怎么改这一段决定你被当资深还是初级
示范（背下来，然后换成自己的）

问题：我们内部有 240 页工程文档，新人查一个问题平均要翻 15 分钟，而且经常查到过期版本。
方案：分三层——解析层用 Docling 保留标题层级；检索层做混合（向量 + BM25）加重排；生成层强制引用编号，并在检索分低于阈值时直接拒答。
数据：30 条人工标注集上正确率 78%，recall@5 0.83（纯向量 0.67），引用可追溯率 96%，首字延迟 p50 1.1 秒。
取舍：最难的是分块。我一开始用固定 400 token，多跳问题几乎全错——因为答案跨两节。改成标题感知并把标题路径拼进块文本后，多跳从 1/6 提到 4/6。代价是块长差异很大，短块多，入库数涨了 40%。现在回头看，我会给短块加合并逻辑，而不是靠重排去救。

每个项目必须预演的 8 个追问
#追问他在考什么你的答案必须有
1为什么不用 LangChain / LangGraph？技术选型判断力具体需求（比如审批中断）+ 框架缺什么 + 你付出了什么代价
2这个 78% 是怎么测的？谁标的？数据严谨性样本量、类型分布、标注方式、judge 与人工一致率
3剩下 22% 错在哪？是否真做过归因分层归因（检索/生成/数据），最好说 2 个具体 case
4如果文档从 240 页涨到 24 万页，什么会先坏？规模化思考具体的瓶颈（索引构建时间 / 检索延迟 / 元数据管理），不要泛泛说「要分布式」
5你怎么知道改了之后更好？评测意识eval 集 + 改动前后对比 + 哪几条 case 翻转
6线上出过一次什么问题？真实经验具体故障 + 你怎么定位 + 怎么修的 + 加了什么防复发
7这个方案的成本是多少？怎么降的？工程经济性单任务成本、最贵的一环、降本手段 + 质量验证
8如果重做一遍，你会改什么？反思能力具体的一个技术决策 + 为什么当时错了
产物三个项目各一份 notes/pitch-项目名.md（90 秒稿 + 8 个追问的答案）+ 录音
验收录音回听：90 秒内讲完四段、没有「嗯/那个/就是说」超过 3 次、第 4 段能自然说出代价。
卡住怎么办
  • 「讲不完，总想讲细节」：细节是留给追问的。90 秒版只讲「结构 + 判断」，细节讲多了会被打断，反而显得不会抓重点。
  • 「第 8 题答不出来」：说明你还没真正复盘。回 P4 的错题本，那里有你当时的痛。
P6-4 20 道高频题：按域分组，每题 2 分钟脱稿 周日 3h
为什么：这 20 题覆盖了 AI 应用岗技术面的绝大部分。不是背答案，是背「答题骨架 + 一个具体例子」。

检索与 RAG（5 题）

#题骨架
1RAG 的完整链路，离线/在线各做什么解析→分块→embedding→索引 / query 改写→混合检索→重排→上下文组装→生成→引用校验
2分块大小怎么定？切分策略怎么选从结构出发（标题）→ token 兜底 → 用 recall@5 验证 → 说清「结构感知的代价是块长不均」
3召回不相关，怎么判断是 embedding 还是切分问题五步排查（语料有无→切分是否完整→是否进前 k→排名→上下文是否被截）
4为什么需要重排？它能否提高召回双塔快而粗、交叉编码器准而慢；只改顺序不改集合，所以 recall 可能降、MRR 升
5长上下文模型出来了，还需要 RAG 吗新鲜度、权限、成本、可溯源四点上 RAG 不可替代；长上下文解决的是「一次能看多少」

Agent 与工具（5 题）

#题骨架
6Agent 和 workflow 怎么选下一步由谁决定；能画成固定流程图就别用 agent；给一个「看似 agent 实则 workflow」的例子
7工具怎么设计？数量和粒度description 写「做什么+何时用+何时不用」；工具间不重叠；12 个降到 6 个跑 eval 看准确率
8死循环怎么防三层：重复调用检测 / token 预算 / 总超时；每层拦什么说清
9上下文满了怎么办四种策略（窗口/摘要/结构化抽取/外置检索）+ 你的组合 + 什么绝不能丢
10MCP 是什么，解决什么问题工具协议；N×M 适配问题；对比「每个客户端各写一遍」

评测与可靠性（5 题）

#题骨架
11你怎么评测一个 LLM 应用测试集构造（类型分布+含失败用例）→ 分层指标（检索/生成）→ judge 校准 → CI 集成
12LLM-as-judge 的偏差和校准长度偏好/自我偏好/位置偏差；一致率检验；prompt 里禁止以长度扣分
13线上效果突然变差，怎么查按时间对齐：模型版本变了吗→prompt 改了吗→数据变了吗→流量构成变了吗；trace 逐层看
14怎么防止 agent 干危险操作最小权限（凭据只读）+ 参数白名单 + 审批 + 审计日志；说清「prompt 不够」
15怎么降成本/延迟四段分解→路由→缓存（前缀/结果）→压缩输入→并行；每次都要带质量验证

工程与协作（5 题）

#题骨架
16需求说「做个 AI 客服」，你怎么拆先定成功判据（解决率/转人工率）→ 划边界（能做什么不能做什么）→ 最小闭环→ 再扩
17模型升级了，要不要切用 eval 对比（不是看榜单）→ 看边缘 case 和成本/延迟 → 灰度 → 保留回滚
18怎么和非技术的人解释不确定性用「可答/需确认/拒答」三档代替百分比；给兜底路径
19你怎么跟进这个领域说具体来源（官方 engineering blog、几个仓库的 release）+ 你怎么筛选（只信有数据的）
20你缺什么诚实说一个真实短板 + 你的补法 + 已经做了什么
答题四件套（每个回答都套这个结构）

一句话结论（先给判断）→ 两三点理由（带对比）→ 一个我自己的例子（真实数据）→ 代价或边界（什么时候不适用）。
这个结构的价值是：即使你某个知识点记不清，前两句也能撑住场面，不会一开口就乱。

产物notes/interview-20.md：每题 5 行（结论/理由/例子/代价）+ 20 段录音
验收随机抽 5 题，2 分钟内讲完且包含一个真实例子；不看笔记能讲。
卡住怎么办
  • 「背不下来」：不要背文字，背骨架关键词（比如第 8 题就记「重复/预算/超时」三个词）。面试时按关键词展开。
  • 「没有真实例子」：说明前面 20 周有任务卡没做。用你现在有的项目例子也行，但要能说出具体数字。
P6-5 反问与薪资：别在这一步丢分 周日 1h
为什么：反问是唯一由你主导的环节，也是判断「这地方值不值得去」的唯一机会。问「团队现在最大的技术难题是什么」比问「加班多吗」得到的信息多十倍。
按轮次准备反问
轮次问什么为什么问这个
技术面「你们现在的评测是怎么做的？有没有固定的测试集？」
「agent 的失败主要是哪一类？」
「这个岗位前三个月最想解决的一个问题是什么？」		试探团队成熟度；也让你了解真实工作
负责人面「这个方向半年内的目标是什么？怎么衡量成功？」
「团队现在几个人，分工怎么划？」
「如果我来了，第一阶段你会怎么判断我做得好不好？」		判断是否有明确目标，还是「先招个人试试」
HR 面「这个岗位的晋升路径是什么？」
「团队过去一年有几个人内部转岗过来？」		判断转岗者是否被接纳（对你是关键信号）
薪资：三个原则
  1. 不在第一轮主动报数字。被问期望时说：「我更关心岗位和团队，薪资可以参考你们这个级别的区间。」如果必须给，给一个区间且下限是你的底线。
  2. 转岗不必然降薪。你的十年工程经验是可迁移资产，不要因为「转行」自我压价。合理参照是「同级后端/全栈」而非「应届 AI」。
  3. 问清总包结构：base / 奖金 / 期权（行权价、成熟期、回购条款）。期权在早期公司可能价值为零，别把它算进对比。
产物notes/questions-to-ask.md：按轮次各 3 个问题
验收每个问题都能引出对方的实质回答（不是「挺好的」）。
卡住怎么办
  • 「不好意思问」：不问才是损失。你在评估一个要待 2 年的地方，信息不对称的代价远大于尴尬。
  • 「被压价」：拿同级岗位的公开区间做参照，不要用「我原来多少」。如果对方坚持按转岗定级，问「多久能重新评估」。

W24投递与迭代：用真实反馈校准

第 24 周 · 投递不是「广撒网」，是小批量 + 快速复盘 + 改材料。

P6-6 三批投递法：先投「练手档」，别先投最想去的 周日 2h + 后续
为什么：你只有一次「第一印象」。先投最想去的公司，你会用还没校准的材料去撞。先投 C 档练手，把话术和材料调到能用，再投 A 档。
批次投谁数量目的结束后做什么

第三批A 档（最想去）4 家冲刺此时材料与话术已迭代 2 轮

如果连续 10 家简历关都过不了

按这个顺序自查：① 岗位类型错配（投了算法岗？）② 简历里没有「AI 相关关键词」（ATS 筛不到）③ 项目描述像教程复现（没有取舍和数字）④ 内推渠道缺失（纯海投转化天然低）。先改这四条，再谈「市场不好」。

产物notes/applications.md（记录表）+ 第一批 6–8 家已投
验收每家都有「下一步」和「反馈」两栏在更新；第一批结束后有一份复盘。
卡住怎么办
  • 「没内推」：翻通讯录、前同事、GitHub 上给你项目点过 star 的人、技术群。内推转化率通常是海投的 3–5 倍，值得花两天找。
  • 「投了没回音」：正常，多数公司不回复。按批次推进，别停下来等。
P6-7 每场面试后 20 分钟复盘（这是提升最快的一步） 每场 20min
为什么：面试的进步不来自「多面」，来自「每场都改一点」。没有复盘的十场面试，等于同一场面了十次。
