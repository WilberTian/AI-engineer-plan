Day 0：把地基打对

这一页大约 60–90 分钟。做完你会有一个 uv 管理的 Python 项目、两家大模型的调用能力、一个能一行命令确认「环境没坏」的自检脚本。后面 24 周每天开工前跑一次自检，能省掉大量「昨天还好好的」类问题。

为什么不用 venv + pip

能用，但你会在 Python 版本、依赖冲突、跨机器复现上反复浪费时间。2026 年的 Python 项目默认用 uv：它同时管 Python 版本、虚拟环境、依赖锁定和脚本运行，相当于 nvm + npm + npx 三合一。你在 JS 里习惯的那套心智可以平移过来。

2一次性安装

按顺序复制。macOS / zsh 环境（Windows 的差异我在每步下面单独标了）。

2.1 装 uv

# 官方安装脚本，装到 ~/.local/bin
curl -LsSf https://astral.sh/uv/install.sh | sh

# 让当前终端立刻生效（新开终端会自动加载）
source $HOME/.local/bin/env

# 验证
uv --version

Windows（PowerShell）：powershell -c "irm https://astral.sh/uv/install.ps1 | iex"。装完关掉终端重开。

2.2 装 Python 3.12 并固定

uv python install 3.12
uv python list | grep 3.12
为什么是 3.12 不是 3.13

不是不能用 3.13，而是 3.12 上几乎所有 AI 相关库（torch 系、某些向量库、老版本 sentence-transformers）的 wheel 都是齐的，踩坑概率最低。等你需要 3.13 的新特性时再加，别在 Day 0 给自己制造不确定性。

2.3 建项目

mkdir -p ~/code && cd ~/code
uv init agentlab --python 3.12
cd agentlab

uv init 会生成 pyproject.toml、.python-version、hello.py。最后这个删掉，我们用自己的结构。

rm -f hello.py main.py
mkdir -p src/agentlab scripts evals data notes tests
touch src/agentlab/__init__.py     # 没有它，hatchling 的 packages=["src/agentlab"] 会让 uv sync 报找不到包

tests/ 先建好：P1-9 会往里放 test_tools.py，pyproject 里的 testpaths=["tests"] 也指在这里。目录不存在的话，第一次跑 pytest 会直接报「file or directory not found」。

2.4 装依赖

# 运行时依赖
uv add openai pydantic python-dotenv httpx tenacity rich

# 开发依赖
uv add --dev ruff mypy pytest

2.5 配置 pyproject.toml

打开 pyproject.toml，在文件末尾追加（保留已有内容，别覆盖）：

[tool.ruff]
line-length = 100
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "SIM"]

[tool.mypy]
python_version = "3.12"
warn_unused_ignores = true
disallow_untyped_defs = true
ignore_missing_imports = true

[tool.pytest.ini_options]
testpaths = ["tests"]
pythonpath = ["src"]

同时确认 pyproject.toml 里有这一段（uv 新版会自动加，没有就补），这样 src/ 下的包能被直接 import：

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["src/agentlab"]

然后：

uv sync
uv run ruff check .
uv run mypy src

如果 ruff 报的是 hello.py 或空目录问题，先建 src/agentlab/__init__.py（空文件）再跑。

4依赖为什么是这几个

包用途为什么是它可能换掉的情况
openai调模型事实标准。国内厂商（DeepSeek / 通义 / Kimi / 智谱）几乎都提供 OpenAI 兼容端点，一套客户端打通需要 Anthropic 原生能力（cache_control、prompt caching 精确控制）时再加 anthropic
pydantic结构化输出校验等价于 Zod。模型的 JSON 输出必须过校验才能进业务不换。这是 Python AI 生态的地基
python-dotenv读 .env本地开发标配上线换环境变量注入
httpx异步 HTTPW3 会手写一次 SSE 流式解析，用官方 SDK 之外的方式理解流不想手写就用 SDK 的 stream
tenacity重试W14 的退避重试用得上，现在先装着可自己写 30 行
rich终端输出调试 agent 时打印结构化的步骤，比 print 强一个量级可换 loguru
ruff / mypylint / 类型对应 ESLint+Prettier / tsc。你写 TS 的习惯直接复用mypy 可换 pyright

故意没装的：LangChain、LangGraph、LlamaIndex、向量库客户端、ragas、langfuse。原因很简单——P1 要求你手写，装框架会让你忍不住绕过。每装一个框架，都要等到对应周才装。

三条硬规矩

1. 新建仓库第一件事是写 .gitignore，不是第一次 commit 之后补。key 一旦进了 commit 历史，删文件也没用，必须换 key。
2. 每个厂商单独建 key，别用一把 key 打通所有环境，泄露时你连「哪来的」都查不到。
3. 在代码里只从 config.py 读配置，业务代码里出现第二个 os.getenv 就算违规——这是你以后做多租户、做多模型的必要条件。

5.4 写 src/agentlab/config.py

"""集中读取环境变量。业务代码不允许直接 os.getenv。"""
from __future__ import annotations

import os
from dataclasses import dataclass
from pathlib import Path

from dotenv import load_dotenv

# 从项目根目录加载，不管从哪里启动都能找到
ROOT = Path(__file__).resolve().parents[2]
load_dotenv(ROOT / ".env")


@dataclass(frozen=True)
class ProviderConfig:
    name: str
    api_key: str
    base_url: str
    model: str

    @property
    def configured(self) -> bool:
        return bool(self.api_key)


def _provider(prefix: str, default_model: str) -> ProviderConfig:
    return ProviderConfig(
        name=prefix.lower(),
        api_key=os.getenv(f"{prefix}_API_KEY", ""),
        base_url=os.getenv(f"{prefix}_BASE_URL", "https://api.openai.com/v1"),
        model=os.getenv(f"{prefix}_MODEL", default_model),
    )


PRIMARY = _provider("PRIMARY", "gpt-4.1-mini")
SECONDARY = _provider("SECONDARY", "deepseek-chat")

# 全局策略：写代码时用的默认值
MAX_OUTPUT_TOKENS = 2048
TEMPERATURE = 0.2
REQUEST_TIMEOUT_SECONDS = 60

注意 parents[2]：文件在 src/agentlab/config.py，往上三层才是项目根。如果你改成别的布局，这行要跟着改——这是新手最容易错的一处。

6接两家模型

为什么必须两家

不是「多备份」这么简单。两个真实理由：（1）P4 要做模型路由和成本对比，没有第二家你没法证明「降级到便宜模型后质量没掉」；（2）有些能力在不同厂商上行为不同（JSON 模式的严格程度、tool calling 的并行支持、缓存机制），只摸过一家的人面试时会被问穿。

选型建议：

组合适合注意
OpenAI + DeepSeek最省事，两个都是 OpenAI 兼容协议，一套代码切换DeepSeek 的 JSON 模式对 schema 描述要求更严
Anthropic + 国内一家想学 prompt caching 和 MCP 原生生态Anthropic 用独立 SDK，接口不兼容，需要适配层
两家国内（如通义 + 智谱）网络稳定、额度便宜复杂 tool calling 的稳定性差异明显，正好用来对比
本地 Ollama 作第二家完全免费、离线可跑，适合 P5 演示延迟高，不适合做首字 < 2s 的验证

给未来留一个适配层的位置

P1 的 W3 你会写 llm.py。现在只需要记住一个原则：上层代码只认「输入消息 → 输出文本或工具调用」，不认厂商。否则 P4 做路由时你要改遍所有调用点。

7自检脚本

把下面完整存成 scripts/check_env.py。它做 6 件事，每件输出一行 OK 或 FAIL，最后给出总结。

from __future__ import annotations

import json
import os
import sys
import time
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
sys.path.insert(0, str(ROOT / "src"))

OK = "  [OK]  "
NO = "  [FAIL]"
results: list[tuple[str, bool, str]] = []


# 每一项都只 record、不抛异常：一项失败不能中断整轮，
# 否则你只会看到第一个问题，修完再跑又冒一个。
def record(name: str, passed: bool, detail: str = "") -> None:
    results.append((name, passed, detail))
    print(f"{OK if passed else NO} {name}" + (f" — {detail}" if detail else ""))


def check_python() -> None:
    v = sys.version_info
    record("Python 版本 ≥ 3.12", v >= (3, 12), f"当前 {v.major}.{v.minor}.{v.micro}")


def check_imports() -> None:
    missing = []
    for mod in ("openai", "pydantic", "dotenv", "httpx"):
        try:
            __import__(mod)
        except ImportError:
            missing.append(mod)
    record("依赖已安装", not missing, "缺少: " + ",".join(missing) if missing else "openai/pydantic/dotenv/httpx")


def check_config():
    from agentlab.config import PRIMARY, SECONDARY
    ok = PRIMARY.configured or SECONDARY.configured
    record("至少一家厂商已配置", ok,
           f"primary={PRIMARY.configured} secondary={SECONDARY.configured}")
    # 必须显式返回 None 表示「没得测」。写成 return PRIMARY if ... else SECONDARY 的话，
    # 两家都没配 key 时返回的是一个空壳 Provider 而不是 None，main() 里 `if provider is not None`
    # 恒为真，[SKIP] 那一行就成了永远到不了的死代码——你会收到一堆 AuthenticationError，
    # 但完全不知道原因只是 key 还没填。
    if PRIMARY.configured:
        return PRIMARY
    if SECONDARY.configured:
        return SECONDARY
    return None


# 这一步同时验证三件事：key 有效、base_url 对、模型名存在。
# 三者错任何一个，报出来的都是同一句认证失败，所以必须真发一次请求。
def check_text_call(provider) -> bool:
    from openai import OpenAI
    client = OpenAI(api_key=provider.api_key, base_url=provider.base_url, timeout=60)
    t0 = time.perf_counter()
    try:
        resp = client.chat.completions.create(
            model=provider.model,
            messages=[{"role": "user", "content": "只回复两个字：可用"}],
            max_tokens=16,
            temperature=0,
        )
    except Exception as exc:  # noqa: BLE001
        record("文本调用", False, f"{type(exc).__name__}: {exc}")
        return False
    text = (resp.choices[0].message.content or "").strip()
    ms = (time.perf_counter() - t0) * 1000
    usage = resp.usage
    record("文本调用", True,
           f"{provider.name}/{provider.model} {ms:.0f}ms "
           f"in={getattr(usage, 'prompt_tokens', '?')} out={getattr(usage, 'completion_tokens', '?')} "
           f"回显={text[:12]!r}")
    return True


def check_structured(provider) -> bool:
    from openai import OpenAI
    from pydantic import BaseModel, Field, ValidationError

    class Ping(BaseModel):
        sum: int = Field(description="两数之和")
        reason: str = Field(description="一句话说明怎么算的")

    client = OpenAI(api_key=provider.api_key, base_url=provider.base_url, timeout=60)
    try:
        resp = client.chat.completions.create(
            model=provider.model,
            messages=[
                {"role": "system", "content": "你是计算器。只输出 JSON，字段为 sum 和 reason。"},
                {"role": "user", "content": "17 加 25 等于多少？"},
            ],
            response_format={"type": "json_object"},
            temperature=0,
        )
        raw = resp.choices[0].message.content or ""
        obj = Ping.model_validate_json(raw)
        record("结构化输出 + Pydantic 校验", obj.sum == 42, f"解析结果 sum={obj.sum}")
        return True
    except (ValidationError, json.JSONDecodeError) as exc:
        record("结构化输出 + Pydantic 校验", False,
               f"JSON/schema 不符: {exc}. 若模型不支持 json_object，改用 tool calling 强制")
        return False
    except Exception as exc:  # noqa: BLE001
        record("结构化输出 + Pydantic 校验", False, f"{type(exc).__name__}: {exc}")
        return False


def check_gitignore() -> None:
    gi = ROOT / ".gitignore"
    ok = gi.exists() and any(
        line.strip() == ".env" for line in gi.read_text(encoding="utf-8").splitlines()
    )
    record(".gitignore 已忽略 .env", ok, str(gi) if gi.exists() else "文件不存在")


# 退出码 0 / 1 是给 CI 用的：你自己看一眼也行，但流水线只认退出码
def main() -> int:
    print("\n=== agentlab 环境自检 ===\n")
    check_python()
    check_imports()
    check_gitignore()
    provider = check_config()
    if provider is not None:
        if check_text_call(provider):
            check_structured(provider)
    else:
        print("  [SKIP] 未配置任何厂商，跳过联网检查")

    passed = sum(1 for _, ok, _ in results if ok)
    total = len(results)
    print(f"\n=== {passed}/{total} 通过 ===")
    if passed < total:
        print("未全绿时不要进 P0。先看本页「故障速查」。\n")
        return 1
    print("环境就绪。把这次输出贴进 notes/day0-env.md 作为基线。\n")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

10故障速查

现象八成原因怎么做
zsh: command not found: uvPATH 没生效source $HOME/.local/bin/env；还不行就 echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc 后重开终端
SSL: CERTIFICATE_VERIFY_FAILED公司代理或镜像证书先试 export HTTPS_PROXY=http://你的代理:端口；不要图省事关校验（verify=False），那会掩盖真问题
ModuleNotFoundError: agentlabsrc/ 布局没配对确认 pyproject.toml 里有 [tool.hatch.build.targets.wheel] packages，并跑一次 uv sync
openai.AuthenticationError.env 没被加载，或 key 带空格/引号uv run python -c "from agentlab.config import PRIMARY; print(repr(PRIMARY.api_key[:6]))"，看是否为空或有多余字符
model_not_found / 404base_url 与模型名不属于同一家国内厂商的 base_url 通常是 https://api.xxx.com/v1，模型名要用该厂商的（不是 gpt-4o）
RateLimitError 429免费额度或并发限制调用间加 time.sleep(1)；正式代码用 tenacity 指数退避（P4 会写）
JSON 解析失败 / ValidationError模型不支持 json_object，或 schema 太复杂去掉 response_format，改用 tool calling 强制返回；或把字段压到 3 个以内、每个都写 Field(description=...)
编辑器报红但命令行正常解释器没指向 .venvCmd+Shift+P → Python: Select Interpreter → 选 ./.venv/bin/python
uv sync 极慢默认源在境外export UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple，或写进 pyproject.toml 的 [[tool.uv.index]]
