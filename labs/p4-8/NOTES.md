# P4-8 要点核对表：成本记账

判分：`python3 labs/p4-8/harness/run_checks.py --target <你的项目>`（16 条）

---

## §1 决策点表

| # | 位置 | 手册做法 | 另一种合理做法 | 什么时候该换 | 怎么核你那份 |
|---|---|---|---|---|---|
| 1 | 价格单位 | 美元/百万 token，除数 `1_000_000` | 美元/千 token，除数 1000 | 抄官网价目表时最容易混 | 算「100 万 input」的成本，看是否正好等于单价 |
| 2 | 缓存计价 | `fresh = input - cached`，两段分别乘 | 只记原始 token，成本在报告层算 | 你想保留「厂商原始数」时，但要在报告层补上扣减 | 传 `cached=input`，成本应等于 `input×cached_in` |
| 3 | 缺价处理 | 返回 0.0 | 抛异常 / 用最贵档兜底 | 成本差异影响上线的决策时，用最贵档更保守 | 传一个没定价的模型名，看是 0、报错、还是一笔糊涂账 |
| 4 | 负数保护 | `max(0, input - cached)` | 不夹，交给上游保证 | 上游是不可信数据时必须夹 | 传 `cached > input`，看会不会算出负成本 |
| 5 | 记账粒度 | 每次模型调用一条 `Usage` | 每个 run 一条汇总 | 想知道「哪一步最贵」就必须按调用记 | 一个 run 里有几次模型调用，你就有几条 Usage 吗 |
| 6 | 命中率分母 | `max(1, Σinput)` | 用 `Σ(input-cached)` 做分母 | 后者会算出 >100% 的怪数 | 空列表跑一次，看会不会除零崩 |
| 7 | 精度 | `round(total, 6)` | 存整数微美元 | 单任务成本 <$0.001 时，浮点舍入会吃掉有效位 | 单任务 $0.000004 时你的报告显示几位 |
| 8 | 记账位置 | eval 报告里汇总 | 生产环境每条 run 落库 | 要按租户/按天看成本时 | 你的成本数据在日志里还是在表里 |

第 2 条是这一页的核心。手册注释写得很直白：**不扣 cached 就是同一批 token 算两遍，成本直接虚高一倍**。
但更坏的情况是**方向反了**——虚高的部分正好是缓存省下的部分，于是你会得出「缓存没省多少钱」这个错误结论，
进而把 prompt caching 关掉。

## §2 静默错误清单

| 静默错误 | 现象 | 什么时候暴露 |
|---|---|---|
| 除数写 `/1000` | 成本虚高 1000 倍 | 你会以为「agent 太贵不能用」，其实是算错了 |
| 不扣 cached | 命中率越高、成本越虚高 | 做 prompt caching 优化后发现「没效果」 |
| 不夹负数 | `cached > input` 时出负成本，总额被拉低 | 厂商数据异常的那一天，报告显示成本下降 |
| 未知模型猜价 | 看起来一切正常，某个新模型被按便宜档记 | 换模型后账单对不上账 |
| 只按 run 记账 | 知道总成本，不知道钱花在哪一步 | 想优化时无从下手——这正是本卡的「为什么」 |
| 单次成本太低不看 | `$0.004` 看不出问题 | 按 1000 任务/天换算成月成本才看得见量级 |

最后一条手册专门写了：**`$0.004` 这个数本身没有意义，换算成「1000 个任务/天 = 每月 $120」才有**。
这个换算本身也是面试话术的一部分——面试官问「你这个方案成本多少」时，答单次 $0.004 对方没有感觉。

## §3 参考实现的边界

| 没做 | 为什么可以不做 | 什么时候必须补 |
|---|---|---|
| 没有按时间/租户维度汇总 | 本卡只要求「一次 eval 的成本四行」 | 上线后要按客户算账时 |
| 没有区分重试产生的重复计费 | 每次调用都是真花钱，重试也该算 | 需要「有效成本」时，要标记 `is_retry` |
| 价格表硬编码 | 4 个模型够用 | 模型池超过 10 个时，从配置读 |
| 没有 `p95 latency` | 延迟是 p4-11 的事 | 报告四行里要有 P95，就在 run_eval 层算 |

## §4 一个对照：为什么输入 token 是主要成本

一个典型 agent 任务，5 轮工具调用：

| 轮次 | 输入 token | 输出 token |
|---|---|---|
| 1 | 800 | 120 |
| 2 | 1,300 | 90 |
| 3 | 2,100 | 150 |
| 4 | 3,000 | 100 |
| 5 | 3,800 | 400 |
| 合计 | **11,000** | **860** |

输入是输出的 **12.8 倍**。按 gpt-4.1-mini 的价（in 0.40 / out 1.60），
成本里 input 占 `11000×0.4 / (11000×0.4 + 860×1.6)` = **77%**。

这就是为什么「省输出 token」的优化基本没用，而「压上下文、开缓存」才有用。
你跑完自己的 eval 后，把这两个数代进去算一遍，就知道自己的结构是不是同一回事。
