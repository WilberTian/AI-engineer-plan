# P3-5 接口约定：system prompt 分层组装

判分器只看这一页。

## §1 落点与公共名

```
agentlab/prompt.py
    build_system(extra: str = "") -> str
```

`extra` 是「本次任务补充说明」，可以为空。返回拼好的 system 全文。

## §2 判什么（14 条）

| 组 | # | 断言 |
|---|---|---|
| 五段 | 1–3 | 返回非空；**五个锚点都在**（身份 / 能力边界 / 工具使用规则 / 输出要求 / 当前环境）；**顺序就是这五段**（身份 → 边界 → 工具 → 输出 → 环境） |
| 前缀稳定 | 4–5 | **时间变了，公共前缀仍覆盖前四段**；**`extra` 变了，公共前缀仍覆盖前四段** |
| 末尾追加 | 6 | `extra` 追加在「当前环境」之后 |
| 拼接 | 7 | 段间用空行分隔，且不出现连续三个换行 |
| 内容 | 8–11 | 输出里有「文件…数字」的计数，且与 `data/corpus/` 下 `.md` 的实际个数一致（不是写死的）；能力边界里写着 `data/` 与 `notes/`；工具规则里有**数字形式**的次数上限（`\d+ 次`，如「最多 6 次」）；输出要求里有「不确定」的处理 |
| 干净 | 12–14 | `extra` 为空时不留「本次任务补充说明」空标题；同一时刻两次调用逐字相同；动态段里不混入静态规则 |

**第 4、5 条是这张卡的全部意义**。缓存按**前缀匹配**，前缀一变缓存全废。
判分器的做法是：把模块里的 `datetime` 换成一个假钟，两次调用取不同分钟，
然后算公共前缀——公共前缀必须覆盖到「输出要求」段结束为止。

只要「当前环境」排到了四段之前，公共前缀就短了，延迟和成本一起回来，
**而代码看起来完全正常**。这就是它值得单独判的原因。

## §3 不判什么

- **prompt 写得好不好**：措辞、语气、要不要 few-shot，都判不了。
- **缓存命中率**：要真跑两次请求看 `cached_tokens`。这里只判**前缀稳定**这个必要条件。
- **`datetime` 换别的方式取时间**：如果你用 `time.strftime` 或 `os.environ`，
  假钟打不进去，第 4 条会报「两次输出完全相同」并给出说明。这时改 CONTRACT 或
  在 `build_system` 里留一个可注入的时钟参数。

## §4 你的自由

- 每段的措辞和长度
- 是否拆更多段（七段也行，只要**越靠前越稳定**）
- 环境段里放什么（时间、文件数、可用工具数、用户偏好都行）
- 是否把工具 schema 也拼进来（判分器不管，但注意它会进前缀）
