## §1 决策点表

| # | 位置 | 手册做法 | 另一种合理做法 | 什么时候该换 | 怎么核你那份 |
|---|---|---|---|---|---|
| 1 | 阈值来源 | 常量 0.35 | 从 unanswerable 集算出来 | **一定要换**：0.35 是占位数，你的 embedder 分数分布和它无关 | 把 3 条不可答 + 12 条可答的最高分打出来看区间 |
| 2 | 第二层识别 | 关键词「资料中没有」/「无法回答」 | 结构化输出（`{"refuse": true}`） | 模型经常换说法时 | 统计 20 次拒答里关键词命中几次 |
| 3 | 层级顺序 | 先门槛后模型 | 先模型后校验分数 | **别换**：先调模型再判分数，钱已经花掉了 | 空 chunks 时看有没有调模型 |
| 4 | 边界 | `< 0.35` | `<= 0.35` | 分数量化到 0.05 且大批样本踩线时 | 数一下有多少条正好 0.35 |
| 5 | 空回复 | 当 answered（**缺陷**） | 当拒答 / 当失败 | 必须换，见 §2 | 让模型返回空串，看 reason |
| 6 | 第三层 | 无 | 引用校验：答案里的引用必须在 chunks 里 | 出现「编造来源」时 | 抽查 5 条答案，引用是不是都在 chunks 里 |

## §2 参考实现的问题：空回复被记成 answered

```python
raw = llm.chat([...])
if "资料中没有" in raw or "无法回答" in raw:
    return REFUSE, "refused_by_model"
return raw, "answered"          # ← raw 是 "" 也走这里
```

实测：模型返回 `""` → `("", "answered")`。判分器第 12 条抓的就是这个。

**为什么这是错的**：`answered` 会进通过率的分母，也会让「拒答率」看起来正常。
但用户看到的是空白。更糟的是它会掩盖一类真实故障——**模型调用超时被上游
吞掉，返回空串**，这种情况在日志里和「正常回答」长得一模一样。

**修法**（任选其一，别选「不管」）：

```python
if not raw.strip():
    return REFUSE, "refused_empty"          # 加第四种原因，指标里单独一格
if "资料中没有" in raw or "无法回答" in raw:
    return REFUSE, "refused_by_model"
```

加第四种原因要同步改 CONTRACT 的白名单——这也是为什么原因字段必须是**枚举**：
多一个值，所有按原因分组的统计脚本都会静默漏数。

## §3 静默错误清单

| 静默错误 | 现象 | 什么时候暴露 |
|---|---|---|
| 只做第二层（没有硬门槛） | 证据为空也调模型，得到自信的编造 | 用户问语料外的问题，得到一段像模像样的假答案 |
| 阈值抄 0.35 | 拒答率高低全看运气 | 换 embedder 之后拒答率突然 60% |
| `<=` 而不是 `<` | 踩线样本全被拒 | 拒答率偏高但没人知道为什么 |
| 只认一个拒答短语 | 拒答率被低估一半 | 线上用户说「它乱答」，离线拒答率只有 5% |
| 两种拒答原因合并 | 分不清是门槛拦的还是模型拒的 | 想调阈值时无从下手 |
| 空回复记成 answered | 空白答案算成功 | 用户投诉「它什么都没说」但报表全绿 |

## §4 一个判断：阈值到底怎么定

手册说的做法是对的，但有一句容易被略过：**如果两个区间重叠严重，说明检索质量
还不到能拒答的程度——回去修分块，别硬调阈值。**

这句话可以变成一个可算的数。把 15 条样本的最高分排序：

| 情况 | 分布形态 | 该怎么办 |
|---|---|---|
| 可分 | 可答组最低分 > 不可答组最高分 | 阈值取中间，一次就成 |
| 轻微重叠 | 重叠 1–2 条 | 接受，阈值取重叠区中位，记下代价 |
| 严重重叠 | 重叠 4 条以上 | **别调阈值**，改分块或换 embedder |

第三种情况硬调阈值的后果是：无论取哪个值，都有一批可答题被拒或不可答题被答。
这不是阈值问题，是**分数本身没有区分度**。这时候调阈值只是把错误从一类
挪到另一类，而你还以为自己优化了。

判断只需要 15 条样本 + 半小时。这比先写第三层校验快得多。
