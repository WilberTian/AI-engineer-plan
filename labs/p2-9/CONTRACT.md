# P2-9 接口约定：引用机制

判分器只看这一页。

## §1 落点与公共名

```
agentlab/rag/cite.py
    build_context(chunks: list[tuple[str, str]]) -> str      # (来源, 正文) → 带 [n] 编号的上下文
    CITE: re.Pattern                                          # 匹配 [n]
    CiteCheck(cited, invalid, uncited_sentences) / .ok
    check(answer: str, n_chunks: int) -> CiteCheck
```

编号从 **1** 开始（system 里写的是「编号对应资料块序号」）。

## §2 判什么（14 条）

| 组 | # | 断言 |
|---|---|---|
| 编号 | 1–5 | 从 1 起、数量与块数一致、每块带来源、块间空行、空资料→空串 |
| 提取 | 6–9 | 合法引用提取；超范围判非法；`[0]` 判非法；重复去重 |
| 覆盖 | 10–12 | 发现未引用句；拒答句豁免；`ok` 判据一致 |
| 漏检 | 13–14 | **短句也检查**；**英文句子也被切分** |

## §3 不判什么

- **模型会不会真的标注引用**：要真实答案样本（30 条 eval 的答案），离线做不到。
- **引用对不对**（引的 [2] 是否真支持那句话）：这需要语义判断，属于 judge 的活。
- **`ok` 的宽松度**：手册允许 1 句未引用即通过，这是设计选择，判分只要求「判据自洽」。

## §4 你的自由

- 编号用 `【1】` / `[1]` / `(1)`——但 `CITE` 正则和 `build_context` 必须一致
- 未引用句用「按长度过滤」还是「全查」
- `ok` 阈值改成「0 句」或「≤10%」

## §5 怎么跑

```bash
python3 labs/p2-9/harness/run_checks.py --target ~/code/agentlab-project
```

## §6 边界：参考实现有 2 条红

两者都是**漏检**，不是算错：

1. `len(s.strip()) > 15` 过滤短句 → **14 字的结论句整句跳过**。「Token 上限是 8000」这种最需要引用的事实句刚好被漏掉。
2. 分句只用 `[。\n]` → **英文整段算一句**，一段三句英文里只要有一处引用，整段就算「已引用」。

修法见 NOTES §2。
