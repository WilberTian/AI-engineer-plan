## §1 决策点表

| # | 位置 | 手册做法 | 另一种合理做法 | 什么时候该换 | 怎么核你那份 |
|---|---|---|---|---|---|
| 1 | 编号基数 | 从 1 起 | 从 0 起 | **别换**：人读、模型写都是「第 1 块」 | 打印 context 看前两个编号 |
| 2 | 编号形式 | `[1]` | `【1】` / `[doc-1]` | 文档本身含 `[1]` 这类字面量时（会撞） | 你的语料里有没有方括号数字 |
| 3 | 来源标注 | `(src)` 跟在编号后 | 只给编号，来源放单独的表 | 模型可能把长路径当正文复述 | 看模型答案里有没有抄路径 |
| 4 | 分句 | `[。\n]` + 长度 >15 过滤 | 全查 + 中英文标点都切 | **必须换**，见 §2 | 传三句英文、传 14 字短句各试一次 |
| 5 | 豁免规则 | 含「资料中没有」不判未引用 | 显式标记 `<refused/>` | 用标记更可靠（关键词会被复述触发） | 模型答「资料中没有提 X，但[1]说了 Y」时怎么判 |
| 6 | ok 阈值 | `len(uncited) <= 1` | `== 0` | 严格模式（合规场景） | 两句答一句带引用，你的 ok 是 True 吗 |
| 7 | 校验时机 | 生成后校验 | 生成时用工具强制 | 要 100% 有引用就只能靠结构化输出 | 你的校验失败后做什么——重试还是只记录 |
| 8 | 引用粒度 | 每句 | 每段 | 段落引用会让「精度」指标失效 | 你的答案里平均几句一个引用 |

第 6 条的「允许 1 句未引用」是个有意思的取舍：它给模型留了一个「过渡句」的余地
（比如「综上，可以得出结论：」这种不需要引用的句子）。代价是真的漏一句你也发现不了。
合规场景下应该设成 0。

## §2 参考实现的两个漏检（判分器已抓住）

### 1. 短句被整句跳过

```python
sentences = [s.strip() for s in re.split(r"[。\n]", answer) if len(s.strip()) > 15]
```

`"Token 上限是8000"` 是 14 字，**不进候选，也就永远不会被判未引用**。

为什么这很糟：**短句往往是最需要引用的事实句**。长句通常是解释（可以不带引用），
短句是结论和数字（必须带）。这个过滤器恰好把该查的都滤掉了。

修法：去掉长度过滤。短句误报的代价，远小于漏检事实句。

### 2. 英文整段算一句

`re.split(r"[。\n]")` 只认中文句号。`"A works. B works. C matters."` 整段是一个「句子」，
只要末尾有个 `[1]`，整段就算已引用——中间两句没来源也查不出来。

修法：`re.split(r"[。\.\!\?！？\n]", answer)`，并排除小数点（`3.5` 会被切断）。

## §3 静默错误清单

| 静默错误 | 现象 | 什么时候暴露 |
|---|---|---|
| 编号从 0 起 | 模型引 `[0]`，校验按 1 起判非法 | 全量标红，或者反过来 `[0]` 被放行 |
| build_context 和 check 的基数不一致 | 引用全对但全判非法 | 第一次跑校验就红一片 |
| 短句过滤 | 短事实句漏检 | 用户点开一个数字，找不到来源 |
| 只认中文句号 | 英文答案覆盖率虚高 | 多语言场景 |
| 来源路径混进正文 | 模型复述路径，答案脏 | 答案里出现 `notes/chunk-a.md` |
| 校验失败只记录不重试 | 引用率永远停在 82% | 你以为「模型就这样」 |

最后一条最容易被接受成「模型能力问题」。实际上引用率 82% 的原因常常是
**校验没有回到生成**：你发现了 18% 的漏引用，但只是记了一笔，没有让它重答一次。

## §4 引用机制值不值这个成本

三段成本：上下文里多 `[n] (src)` 的字符（约 5%）、校验的一遍正则（可忽略）、
以及**漏引用时的重试**（这才是大头）。

判断值不值的标准很直接：

| 场景 | 引用值不值 |
|---|---|
| 客服/合规/医疗，答案会被当成依据 | 值。没有引用等于没有答案 |
| 个人助理，答错代价低 | 不值。多 5% token 和重试成本换不来什么 |
| 面试/作品集演示 | 值。它是「可验证」最直观的证据 |

这张表也解释了为什么 P2 把引用放在这里：它不是 RAG 的装饰，是**让 RAG 的输出可以被查证**的机制。
