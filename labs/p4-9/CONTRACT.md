# P4-9 接口约定：模型路由

判分器只看这一页。

## §1 落点与公共名

```
agentlab/routing.py
    Route(name: str, model: str, reason: str)
    route(task: str, history_len: int, has_tools: bool) -> Route
```

档位名固定三种：`simple` / `default` / `hard`。模型名由你定。

## §2 判什么（14 条）

| 组 | # | 断言 |
|---|---|---|
| 三档可达 | 1–4 | 短问题→simple；长+难度标记→hard；长+无标记→default；**三档用三个不同模型** |
| simple 边界 | 5–7 | 带工具不判 simple；有历史不判 simple；长度阈值真的起作用 |
| hard 信号 | 8–11 | 七个难度标记（分析/对比/为什么/设计/重构/debug/证明）都升 hard；**短但含标记仍 hard**；长历史升 hard；**边界落在 10/11 之间** |
| 可解释 | 12–14 | 每档 reason 非空；同输入结果稳定；没有走不到的档位 |

**边界值是写死的**：`len(task) < 40` 进 simple、`history_len > 10` 升 hard。改这两个数会让第 7、11 条红——
这是故意的，边界挪一格不报错，只是某一类任务被静默降级。

**用例长度都在 40 字以上**（simple 门槛之外），否则测出来的是长度规则而不是难度信号。

## §3 不判什么

- **「成本降 ≥30%、通过率掉 ≤2 点、每档掉点 ≤5」**：这是本卡的验收，但它需要真跑 eval 的两组对照（路由后 vs 全大模型）。离线判不了。
- **分类质量**：「这个任务该不该用大模型」是判断，不是断言。
- **模型选得对不对**：`gpt-4.1-mini` 还是 `deepseek-chat` 由你定，只判「三档不是同一个」。

## §4 你的自由

- 加第 4 档（比如 `tiny` 或 `vision`）
- 用分类器替换关键词规则（但要保持边界可预测，第 7、11 条仍会卡边界值）
- reason 的措辞
- 从配置读模型名

## §5 怎么跑

```bash
python3 labs/p4-9/harness/run_checks.py --target ~/code/agentlab-project
```

## §6 边界：参考实现有 1 条红

`设计一个分块策略`（8 字，无工具无历史）被判成 **simple**，因为它先过「短问题」规则，
再判难度标记——难度信号被长度规则吃掉了。修法见 NOTES §2。

顺带一个更值得注意的事实：**40 字的阈值对中文太高**。中文 40 字已经是相当长的提问，
所以现实中大部分任务都会落进 simple，`default`/`hard` 只在超长或长历史时触发。
判分器把用例都控制在 40 字以上，就是为了不让这个偏移掩盖分类逻辑本身的问题。
