# labs

配套**判分器和核对表**。手册负责讲，这里负责判——判你写的代码符不符合手册的接口约定。

24 个 lab，**336 条判据**，不联网、不花额度、不需要 pytest。

## 一条硬规则：这里不放第二份代码

参考实现就在手册正文里（`stage-p1.html#p1-10` 这类卡片）。仓库里再存一份副本，
两边迟早不一致——改了一边忘另一边，不报错，只是悄悄变成两套说法。

所以 `tools/verify_reference.py` 的做法是**从 HTML 里现抽**代码再跑判分。
手册改了，判分跟着变；对不上就是真问题。

## 目录约定

```
labs/
├── _shared/                  所有 lab 共用，不重复实现
│   ├── checkkit.py           统一的检查表执行器（打印格式 + 退出码 + --filter）
│   ├── htmlcode.py           从手册 HTML 现抽代码块 + sha256 指纹
│   ├── refkit.py             verify_reference / self_test 的薄壳（判代码）
│   ├── datafix.py            verify_ok / self_test 的薄壳（判数据文件）
│   └── mutate.py             判分器体检引擎（塞 bug → 断言必须红）
└── p4-4/                     每个 lab 长这样
    ├── CONTRACT.md           接口约定——判分只看这一页
    ├── NOTES.md              决策点表 + 静默错误 + 参考实现的边界
    ├── harness/
    │   ├── fake_llm.py       假 provider / 假 SDK（只有需要的 lab 才有）
    │   └── run_checks.py     断言，判你自己的实现
    └── tools/
        ├── verify_reference.py   从手册抽参考实现，跑同一套断言
        └── self_test.py          往参考实现里塞已知 bug
```

三个判数据文件的 lab（`p1-12` / `p2-12` / `p2-15`）略有不同：

- 它们**没有参考实现可抽**——手册只给了一行格式样例，30 条测试集是读者自己写的
- 所以 `tools/` 下是 `verify_contract.py`（按 CONTRACT 造一份**最小合规夹具**，
  14 条必须全绿，证明判据不是恒假的）+ `self_test.py`（把夹具弄坏一处，对应那条必须变红）
- `p5-14` 也不走 refkit：它的两个代码块对应两个文件，`verify_reference.py` 自己拼

## 怎么用

**读者**（写完对应的卡之后）：

```bash
python3 labs/p1-10/harness/run_checks.py                  # 默认在 ./src 找 agentlab/
python3 labs/p1-10/harness/run_checks.py --target ~/code/x/src
python3 labs/p1-9/harness/run_checks.py  --filter 候选     # 只跑某一条
uv run python labs/p1-2/harness/run_checks.py             # p1-2 需要 pydantic
python3 labs/p1-13/harness/run_checks.py --script ~/code/x/evals/run_eval.py
```

**维护者**（改过手册里那段代码之后）：

```bash
python3 labs/p1-10/tools/verify_reference.py   # 参考实现必须符合已知预期
python3 labs/p1-10/tools/self_test.py          # 判分器必须能抓住已知 bug
```

第二个命令比第一个重要：**一个永远通过的判分器等于没有判分器。**

## 判分能管到哪

| | |
|---|---|
| 能判 | 协议层与接口层：消息序列、`tool_call_id` 对应、回填、兜底出口、错误回灌、截断、路径沙箱、业务规则、通过率、分布、前缀稳定性、耗时、调用参数 |
| 判不了 | 模型行为：会不会选对工具、会不会靠错误信息自我修正、prompt 写得好不好、哪个特性真有用 |

判不了的原因不是懒：真模型每次回答都不同，结果不可复现。**不可复现的东西不能当判据，只能当观察。**

## 新增一张卡时的五条约束

1. **不存代码副本**——用 `_shared/htmlcode.py` 从 HTML 拿
2. **判据只写在 `CONTRACT.md` 里**——没写进去的一律不判，否则读者的合理实现会被判错
3. **必须带 `self_test`**——至少塞 3 个已知 bug，且每个 mutation 打**不同的**检查
4. **必须能离线跑**——不联网、不花额度、不依赖 pytest
5. **失败消息要可操作**——写清实际值、期望值、为什么这条重要。只写「不匹配」等于没写

## 四个容易踩的坑（都已经踩过）

- **断言可能在「因为没执行」的情况下通过**。p1-2 的 `refused=True` 那条一开始就是：
  validator 根本没跑，于是「合法数据通过」——测试绿了，规则是坏的。
  p1-8 的「超长消息被截断」也是同类：参考实现一次都没调到 SDK，
  截断那行代码永远不执行，于是它「通过了」。现在这条会额外要求
  「观察到一条接近 200 字的消息」——**不执行就不算过**。
- **断言可能区分不了两种行为**。p1-9 的 `..` 那条一开始也是：删掉沙箱后
  文件照样读不到，`ok=False` 依然成立。判据要选「只有正确实现才能满足」的观测点。
- **阈值不要绑魔数，要绑结构**。p3-5 判前缀稳定用的是「公共前缀 ≥ 最后一段静态段的
  结束位置」，不是「前 100 字相同」——后者你多写一句就被判红。p3-12 用的是
  `1 + len(history)`，也不是常数。
- **「关掉」不等于「改了」**。p5-14 里 `self_check` 默认就是 `False`，
  `replace(BASE, self_check=False)` 什么也没改，这次对比两边一样、delta 恒为 0，
  而你会读成「这个特性没用」。判据要区分「与默认值相比差几个字段」，不是「设成 False 了几个」。

## 还没有的

- **starter（骨架代码）**：暂不提供。给了骨架就等于替读者做了结构决策，而结构判断是这 24 周要自己长出来的东西
- **solution 单独一份**：不提供，手册正文就是。要对照就对着手册读，`NOTES.md` 告诉你该核哪几处

## 剩下 41 张有代码的卡：做与不做

84 张卡里 65 张有代码块。已配 lab 的 24 张之外，剩下 41 张分三类：

| 类 | 为什么 | 典型卡 | 结论 |
|---|---|---|---|
| **B. 需真依赖** | 有 DB / 外部库，要造假替身才可判 | `p2-2` docling、`p2-3` chonkie、`p2-5` pgvector、`p2-6` rank_bm25、`p3-7`/`p3-8` psycopg、`p3-9` mcp | 成本高、判据容易失真，暂不做 |
| **C. 只能判一半** | 关键验收要真模型 | `p1-5` llm 四方法、`p1-11` 错误回灌实验、`p1-14` judge 一致率、`p2-13` 五个指标、`p4-6` 审计日志（要真 Postgres）、`p4-10` prompt caching（只有结构示意、无可判对象） | 做也只覆盖一半，不如不做 |
| **D. 判不了** | 文档 / UI / 录屏 / 面试 | P0 全 6 张、`p3-1`~`p3-4` 读源码笔记、`p4-5` 威胁模型、`p4-7` 错题本、P5 的 9 张前端、P6 全 7 张 | 不做，也不假装能做 |

「D 类不做」不等于「不重要」——`p4-5` 威胁模型清单、`p6-3` 八追问，都是要自己写的。
只是它们**没有可断言的对象**：写得好的威胁模型和写得差的，判分器区分不出来。

P5 的 9 张前端卡是另一回事：它们**理论上可判**（Playwright 断言首字延迟、三态 UI、流式渲染），
但要另一套工具链（Node + Playwright + 一个能跑起来的 dev server），和现在的 Python 判分器不共用。
要做就得单独起 `labs/web/`，不是加几个文件的事。
