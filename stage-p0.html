三个真实优势（面试里要主动讲）

优势一

全栈闭环

  • 大部分 AI 工程师做不出像样的界面，得找前端合作
  • 你能一个人从模型调用做到界面上线
  • 在小团队 / 创业公司，这是「招来就能干活」的信号
优势二

延迟与不确定性的体验设计

  • LLM 输出天然慢、天然不确定
  • 你做过骨架屏、乐观更新、渐进披露、流式渲染
  • LLM 产品的成败常在「等的那三秒怎么呈现」
优势三

产品判断力

  • Agent 失败案例里，技术不行只占一部分
  • 更常见的是：对话流不自然、错误提示看不懂、用户不知道怎么纠偏
  • 这种直觉很难速成，而你已经练了十年
但必须承认的短板：后端与数据

你常年「调 API」，但很少自己扛 QPS、做队列、设计库表权限。而 RAG 本质是数据工程：入库、增量、删除、权限过滤。面试会问多租户隔离、并发、限流——这块在 P2（权限过滤）和 P5（限额与多租户）专门补，别指望临场糊过去。

能力地图：六个域、四个等级，每一级具体要会什么

一个反直觉的结论

招聘方几乎不问「你会不会用某个框架」。他们问的是「出问题时你怎么定位」和「你怎么证明改了之后更好」。所以「学 3 个框架」的收益，远低于「把 1 个框架 + 1 套评测做透」。这也是为什么这套计划把评测做成贯穿 5 个阶段的线，而不是某一周的课题。

3任务卡

P0-1 先扒 5 份 JD，建立「招聘方在要什么」的真实感 40min
为什么：不要一上来就扒 20 份。先 5 份，你会立刻发现两件事——（1）岗位名字五花八门但要求高度重叠；（2）你以为的必备项（比如微调）出现率其实很低。这个反差会校正你后面的学习优先级。
怎么做
  1. 在三个渠道各搜一轮，用下面这组关键词（别只搜「AI 工程师」）：
    渠道搜索词为什么用这个渠道
    Boss 直聘AI 应用开发、Agent 开发、大模型应用、AI 产品工程师中文岗位样本最多，JD 写得最细
    拉勾 / 猎聘LLM 应用、智能体、AI 全栈中小公司和创业公司多，要求更实在
    公司官网 careers直接进字节 / 阿里 / 腾讯 / 美团 / 小红书 / 月之暗面 / 智谱 的招聘页搜 Agent官网 JD 质量最高，且能看出团队在做什么
  2. 只挑三类岗位，其余忽略：AI 应用 / Agent 开发 AI 产品工程师 / AI 全栈 Agent 平台 / 基础设施。明确不看的：算法研究员、CV/NLP 算法、推荐算法、数据标注。
  3. 存原文：每份 JD 全文复制到 notes/jd/raw/公司-岗位.md。别只存链接，链接会失效，而且你后面要全文检索关键词。
  4. 填结构化表，字段就这 8 个，不要加： 
    id,company,role,type,must_1,must_2,must_3,my_score,evidence
1,某公司,AI应用开发工程师,AI应用,"熟悉RAG与向量检索","Python工程能力","有LLM应用落地经验",1,"做过ES检索但没做过语义检索"
    my_score 用 0/1/2：0 完全没有、1 沾过边、2 能拿出来讲。evidence 必须写具体事实，写「了解」等于没写。
  5. 写三句观察到底部。格式：「5 份里出现最多的是 X（N 次）；最意外的是 Y；最一致的门槛是 Z」。
产物notes/jd/raw/*.md（5 份原文）+ notes/jd/jd.csv（5 行）+ 三句观察
验收 5 份 JD 分属至少 3 家公司、覆盖至少 2 类岗位；my_score 里至少有 3 个 0 分（如果全是 1 分以上，说明你在自我美化）。
卡住怎么办
  • 「搜不到这些岗位」：换搜索词，用「大模型」「LLM」「智能体」「知识库」再搜一轮；或直接搜技能词「RAG」「LangChain」「MCP」。
  • 「JD 写得很虚，看不出要求」：只看「任职要求」和「加分项」两段，忽略职责描述。职责是给 HR 看的，要求才是给你的。
  • 「不知道 my_score 怎么打」：问自己一句话——如果面试官现在问「你做过 RAG 吗」，我能不能讲 2 分钟不重复？能=2，能讲但没做过=1，讲不出=0。
P0-2 补到 20 份，并区分两类公司 2×40min
为什么：20 份才够做频次统计（5 份的偶然性太大）。而且要刻意让样本里有两类完全不同的公司——它们的考点不一样，混在一起统计会失真。
怎么做
  1. 按这个配额补到 20 份：A 类：产品公司自建 AI 能力 12 份 B 类：AI 公司/AI 交付 6 份 C 类：Agent 平台/基础设施 2 份。
  2. 在 CSV 的 type 列区分清楚：AI应用 / AI产品 / Agent平台。

产物notes/jd/jd.csv 20 行 + 每行的 my_score/evidence 齐全

怎么做

    from __future__ import annotations

import csv
import re
from collections import Counter, defaultdict
from pathlib import Path

CSV_PATH = Path("notes/jd/jd.csv")

# 20 个能力项 + 同义词。加词比改脚本便宜，先尽量长。
TAXONOMY: dict[str, list[str]] = {
    "LLM API / Prompt": ["prompt", "提示词", "llm", "大模型", "api 调用", "上下文工程"],
    "RAG / 检索增强": ["rag", "检索增强", "知识库", "召回", "向量检索"],
    "Agent / 工具调用": ["agent", "智能体", "function call", "tool call", "工具调用", "mcp"],
    "评测 / Eval": ["评测", "评估", "eval", "benchmark", "准确率", "效果调优"],
    "向量数据库": ["向量数据库", "milvus", "qdrant", "pgvector", "faiss", "weaviate", "chroma"],
    "微调 / 训练": ["微调", "fine-tun", "sft", "lora", "训练"],
    "多智能体": ["多智能体", "multi-agent", "多 agent", "编排"],

    "安全 / 合规": ["安全", "合规", "风控", "隐私", "脱敏"],
    "数据 / 文档解析": ["数据清洗", "文档解析", "etl", "语料", "标注"],
    "性能 / 推理优化": ["推理优化", "延迟", "并发", "性能优化", "vllm"],
    "产品思维": ["产品", "需求", "用户体验", "交互"],
    "业务领域": ["金融", "客服", "教育", "医疗", "电商", "法律", "saas"],
    "SQL / 数据": ["sql", "mysql", "数据分析", "数仓"],
    "分布式 / 高并发": ["分布式", "高并发", "微服务", "消息队列"],
    "算法基础": ["算法", "数据结构", "leetcode", "手撕"],
}


def hits(text: str) -> set[str]:
    low = text.lower()
    out = set()
    for item, words in TAXONOMY.items():
        if any(w in low for w in words):
            out.add(item)
    return out


def main() -> None:
    rows = list(csv.DictReader(CSV_PATH.open(encoding="utf-8")))
    total = len(rows)
    if not total:
        raise SystemExit("jd.csv 是空的")

    counter: Counter[str] = Counter()
    scores: dict[str, list[int]] = defaultdict(list)
    by_type: dict[str, Counter[str]] = defaultdict(Counter)

    for row in rows:
        text = " ".join(
            [row.get(k, "") for k in ("role", "must_1", "must_2", "must_3")]
        )
        found = hits(text)
        counter.update(found)
        by_type[row.get("type", "?")].update(found)
        for item in found:
            try:
                scores[item].append(int(row.get("my_score") or 0))
            except ValueError:
                scores[item].append(0)

    print(f"\n样本 {total} 份\n")
    print(f"{'能力项':<20}{'出现':>4}{'占比':>8}{'我的均分':>10}")
    print("-" * 44)
    for item, n in counter.most_common():
        avg = sum(scores[item]) / len(scores[item]) if scores[item] else 0
        print(f"{item:<20}{n:>4}{n / total:>7.0%}{avg:>9.2f}")

    print("\n按岗位类型拆分（Top5）")
    for t, c in by_type.items():
        top = "、".join(f"{k}({v})" for k, v in c.most_common(5))
        print(f"  {t}: {top}")

    print("\n=== 缺口排序（出现率高 × 我分数低）===")
    gaps = []
    for item, n in counter.items():
        if n < max(2, total * 0.2):
            continue
        avg = sum(scores[item]) / len(scores[item])
        gaps.append((n / total * (3 - avg), item, n, avg))
    for weight, item, n, avg in sorted(gaps, reverse=True)[:8]:
        print(f"  {item:<20} 出现{n:>3} 均分{avg:.2f} 缺口权重{weight:.2f}")


if __name__ == "__main__":
    main()

  2. 跑：uv run python scripts/jd_scan.py。如果某些高频要求没被词表捕获（看输出里明显缺项），就往 TAXONOMY 加词重跑，别改统计逻辑。
  3. 人工复核一遍：脚本会误判（比如「算法」匹配到了「推荐算法」）。用 10 分钟扫一遍原文，把明显错配的用手工修正写在 notes/jd/notes.md 里。脚本给方向，你给判断。
  4. 写下结论三行：最高频的 5 项、我全缺的 3 项、我原以为重要但频次很低的一项。
产物scripts/jd_scan.py + 一次完整输出的文本（存 notes/jd/scan-output.txt）+ 结论三行
验收 能报出「Top5 高频能力及各自出现率」；能指着一项说「这个我原以为必学，其实只有 3/20 家提到」。
卡住怎么办
  • 「所有项都命中，看不出差异」：词表太宽（比如 llm 几乎每份都有）。把泛词从词表里删掉，只留区分度高的词。
  • 「CSV 读出来是乱码」：Excel 存的 CSV 可能是 GBK。用 encoding="gb18030" 读，或另存为 UTF-8。
  • 「某列有逗号导致串列」：用 Excel/Numbers 正常存 CSV 会自动加引号，但手工写的没有。字段里有逗号就整段用双引号包起来。
P0-4 六域自评：把「我缺什么」变成可打分的表 2h（周六上午）
为什么：你已有十年工程经验，很多能力是「有但没意识到」，也有很多是「以为自己有其实没有」。评分表的作用是逼你给每条找证据——找不到证据的，就是 0 分。打分前先看 能力地图，那里写清了每一级具体长什么样。
怎么做
  1. 用这张表给自己打分。评分标准必须严格按下面四级，不要自定义：
    分含义判据（必须能给出其中一条）
    0没接触说不出这个术语在解决什么问题
    1看得懂能跟着教程跑通，但换一个场景就不会
    2独立做过自己从零搭过一次，能讲清 2 个以上的取舍
    3踩过坑能设计遇到过失败并定位到根因，能设计替代方案并解释为什么
  2. 六个域，每域 4–6 项，逐项打分并写一句话证据：
    域要评的项
    模型层API 调用与参数、流式、结构化输出、tool calling、上下文窗口管理、prompt 结构设计
    检索层文档解析、分块策略、embedding 选型、向量库、混合检索、重排、引用与溯源
    运行时agent loop、工具设计、状态持久化、中断恢复、权限与审批、子 agent
    评测层测试集构造、自动判分、LLM-as-judge、检索指标、回归对比、线上监控
    工程层Python、异步、容器化、可观测性、限流与幂等、成本核算、多租户
    产品层流式交互、错误可读性、生成式 UI、需求拆解、把不确定讲给非技术听
  3. 交叉校验：拿 P0-3 的缺口排序和这张表对照。如果某能力「JD 出现率高 + 我打 0 分」，它就是你这 24 周的第一优先级；如果「出现率高 + 我打 2 分」，那它是你的可迁移优势，要写进简历。

前端背景具体强在哪，打分时别自我压低

「产品层」这一域你大概率能打到 2–3：流式交互、错误可读性、状态管理、组件化——这些是 AI 工程师普遍最弱的地方。面试时这是加分项，但前提是你能把「我做过流式渲染」翻译成「我处理过 token 级增量更新下的 UI 一致性问题」。翻译这件事 P6 会专项练，现在先在表里如实打高分。

产物notes/self-assessment.md（六域 × 24 项，带证据 + 总结句）

卡住怎么办
  • 「每项都像 1 分」：1 分的判据是「换场景就不会」。问自己：给我一个和教程不同的需求，我能不能不查资料做出来？不能就是 1。
  • 「评不下去了，太耗时间」：先只评 12 项（每域 2 项最关键的），2 小时必须结束。这张表在 P4 末会重评一次，那时你自然会更准。
P0-5 简历 v0：把十年经验翻译成 AI 语言 2h（周六下午）
为什么：v0 不是终稿（P6 会重写），它的作用是逼你把已有经历讲成「和 AI 系统相关」。这个过程会暴露一个事实：你的很多经验其实高度相关，只是从来没有用对方的语言说过。
三条改写原则
  1. 只写结果和数字，不写职责。「负责前端开发」是职责；「把首屏从 3.2s 降到 1.1s，转化率提升 4%」是结果。
  2. 每条都回答「你消除了什么不确定性」。AI 系统的核心成本是不确定性，所以最值钱的描述是「我怎么让它变得可预测」——比如「把线上报错归因从人工看日志改成按错误码分层，定位时间从 40 分钟降到 5 分钟」。
  3. 不出现「转型 / 学习中 / 零基础 / 对 AI 感兴趣」。这些词直接告诉对方「我还没有能力」。用事实说话，不用态度说话。
把已有经验做「AI 语言翻译」
你原来的写法问题改成
「负责公司管理后台前端架构，使用 Vue3 + TypeScript」 只说了技术栈，没有结果，也没和 AI 产生关联 「重构管理后台数据层，把 12 个页面的重复请求合并为统一缓存层，接口调用量降 60%；该层后来被复用于内部 AI 助手的会话状态管理」
「有良好的沟通能力和团队协作精神」 零信息量 删掉。换成：「主导 3 个团队的接口契约评审，把联调返工从平均 2 轮降到 0.5 轮」
「了解大模型，熟悉 Prompt 工程」 「了解」在筛简历时按 0 分处理 放进项目里说：「用结构化输出 + 校验重试把信息抽取的格式错误率从 18% 降到 2%（50 条样本）」
「持续学习 AI 新技术，关注 Agent 发展」 态度不能替代能力 删掉。换成 GitHub 仓库链接 + 一句「手写 agent loop 与 eval，见 github.com/xxx/agentlab」
怎么做（具体动作）
  1. 先把现有简历里所有职责句和形容词句删掉，只留含数字的句子。你会发现剩下的不多——这就是你真实的可量化产出。
  2. 对每条剩下的，按「背景 → 动作 → 结果 → 可迁移性」四段重写。可迁移性是最后一句，点明它和 AI 系统的关系（不要硬拗，拗不出来说明这条不相关，删掉）。
  3. 加一个 「项目」区块放 agentlab 仓库。现在它只有环境自检脚本，先如实写「进行中：agent loop + eval 基础设施」，P1 结束后更新为真实数据。不做假，但可以把在建的东西写清楚在建。
  4. 结构按这个顺序（中文简历）：一句话定位 → 技能（按域分，不按熟练度打分）→ 工作经历（倒序，每条 3–4 个 bullet）→ 项目 → 教育。
  5. 一句话定位模板：10 年前端工程经验，专注复杂交互与性能优化；近 6 个月转向 LLM 应用工程，手写 agent runtime 与评测体系。——注意它同时给了「旧优势」和「新动作」。
产物notes/resume-v0.md（纯文本版即可，排版留到 P6）
验收 ① 全文出现至少 3 个量化结果；② 没有「转型/学习/了解/熟悉」这类词（grep -E "转型|学习中|零基础|了解|熟悉" notes/resume-v0.md 应无输出）；③ 任一 bullet 你能对着讲 2 分钟且不重复。
卡住怎么办
  • 「我的工作没有数字」：几乎所有工程工作都有。想想：几个页面/几个接口/多少 QPS/多少用户/多长时间/几个人/几次返工/多少 bug。没有精确值就用范围（「约」「×量级」），别编。
  • 「硬拗不到 AI 上」：那就别拗。简历里 2–3 条 AI 相关 + 5 条扎实的工程结果，比 8 条都硬扯 AI 强得多——后者一眼就能看出在凑。
  • 「写出来像流水账」：每条 bullet 检查一遍：有没有「因为…所以选了…」的因果？没有因果就是流水账。

4闭卷自测

周日晚上合上所有材料，口述回答。答不出来的回对应任务卡重做。

Q1–Q5 本周自测题（点开看答案要点） 20min
Q1 你 20 份 JD 里出现率最高的 5 项能力是什么？各自出现率是多少？

要点：能报出具体数字（如「评测 11/20」）。报不出说明 P0-3 没真跑。这个数字后面会在面试里用到，必须记牢。

Q2 A 类（产品公司自建）和 B 类（AI 公司交付）的要求，差异在哪三条？

要点：A 类更看「业务理解 + 工程落地 + 和现有系统集成」，B 类更看「快速交付 + 方案通用性 + 客户沟通」。两类对「评测」的要求也不同：A 类关心线上效果稳定，B 类关心交付验收。

Q3 你的 5 个缺口分别是什么？为什么是这 5 个而不是别的？

要点：必须能说出筛选逻辑——「出现率高 × 我分数低」。如果只是「我觉得该学」，说明还在凭感觉。

Q4 你原以为必学、但频次很低的一项是什么？

要点：多数人的答案是「微调 / 训练」。这项在应用岗出现率通常远低于 RAG 和评测。能说出这个反差，说明你真的看了数据而不是看文章。

Q5 你的简历里，哪一句最能让面试官想追问？

要点：好的答案是「有数字且有因果」的那句。如果一句都挑不出来，简历 v0 需要重写——简历的目的不是罗列，是制造追问。
